# MVP 요구사항 추적표

이 문서는 `AI_AGENT_DEVELOPMENT_PROMPT.md`의 구현 상태를 추적한다. 완료 표시는 코드, 자동화 테스트, 문서가 함께 검증된 경우에만 사용한다.

## 상태 기준

- `DONE`: 현재 단계의 구현과 검증이 끝남
- `IN PROGRESS`: 일부가 구현되었거나 현재 작업 중
- `PLANNED`: 요구사항은 확정되었지만 아직 구현하지 않음
- `DECISION NEEDED`: 학교 또는 운영 담당자의 결정 전에는 확정할 수 없음

## 공개 제안과 동의

| 요구사항 | 상태 | 핵심 검증 |
| --- | --- | --- |
| 익명/실명 제안 작성 | DONE | 작성자 UUID는 AES-256-GCM 암호문·nonce·키 버전으로 별도 Vault에만 저장 |
| 50명 미만 학생 전용 공개 | DONE | 교사 목록에서 제외하고 직접 상세 UUID 요청도 404로 최소 공개 |
| 작성자 자동 1표 | DONE | 제안·Vault·첫 동의·초기 상태 이력을 단일 트랜잭션으로 저장 |
| 활성 학생만 동의 | DONE | 현재 세션 학생 역할 검증과 DB 유효 동의 집계 시 계정·역할 재검증 |
| `UNIQUE(proposal_id, voter_user_id)` | DONE | 복합 PK 최종 통제와 동시 중복 PUT 멱등 처리 |
| 50명 이전 동의 철회 | DONE | DELETE 멱등 처리, 정식 안건 뒤 충돌 응답 검증 |
| 50명 원자적 승격 | DONE | 제안 행 잠금, 조건부 상태 변경, 단일 이력·알림·스냅샷 동시성 검증 |
| 업무 상태와 공개 상태 분리 | DONE | 독립 DB 컬럼과 allowlist CHECK, append-only 상태 이력 |
| 공식 답변과 실행 이력 | DONE | 내부 지정 담당 교사만 상태별 명시적 명령 사용; 공개 답변·append-only 상태 이력·감사 로그 검증 |

## 신고, 심의, 신원

| 요구사항 | 상태 | 핵심 검증 |

| 신고와 자동 삭제 분리 | DONE | 신고 접수는 공개 상태·Vault를 바꾸지 않으며 사용자+제안 기준 멱등 처리 |

| 고정 심의위원 3명 전원 승인 | DONE | 사건 생성 시 세 현임자를 고정하고 사건 행 잠금으로 중복표·동시 결정을 통제 |
| 학생 임원에게 평문 신원 미노출 | DONE | 일반 사건 DTO는 신원을 포함하지 않고 복호화는 별도 열람 서비스에만 존재 |

| 소프트 삭제와 원문 보존 | DONE | 전원 승인 시 `HIDDEN_BY_DECISION`으로만 전환하고 원문·표·공개 이력을 보존 |

## 확정 전 대기 항목

자세한 내용은 `docs/decisions/open-questions.md`에서 관리한다. 정식 명칭, 디자인 자산, 저작권 주체, 실제 보직자·고충 담당자, 답변/동의 기한, 보존 기간, 운영 인프라, 외부 API는 임의로 확정하지 않는다.
