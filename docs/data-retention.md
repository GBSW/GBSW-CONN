# 데이터 보존과 파기 결정표

## 원칙

법정·학교 정책, 사건 대응과 개인정보 최소화 요구를 함께 승인하기 전에는 기간을 임의로 입력하거나 자동 삭제를 켜지 않는다. 삭제는 Identity Vault, 일반 업무 데이터, 감사 증적과 백업을 구분해야 하며 운영 DB 행을 수동 SQL로 지우는 방식은 허용하지 않는다.

## 구현 전 승인 항목

- 보존 시작 시점, 정지 사유와 법적 보존 예외를 정의한다.
- 원본 삭제, 비식별화, 키 폐기 중 데이터 종류별 방식을 선택한다.
- 공개 제한, 계정 정지와 법적 파기를 서로 다른 상태로 취급한다.
- 감사·심의·신원 열람 기록의 불변성과 개인정보 최소화 충돌을 승인권자가 해결한다.
- 백업 만료가 운영 DB 파기보다 늦을 때 복원 후 재파기 절차를 정의한다.
- dry-run 결과, 삭제 건수, 예외와 실패를 평문 신원 없이 감사 가능하게 기록한다.

승인된 표와 회귀 테스트가 준비되기 전에는 애플리케이션 스케줄러, Flyway 보존 메타데이터 또는 자동 파기 작업을 추가하지 않는다.
